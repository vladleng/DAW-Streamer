# Архитектура DAW Streamer

Статус: проект архитектуры. Детали протокола и синхронизации предстоит проверить прототипами.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| plugin/ | Пропуск входного аудио без изменений, отправка копии, индикация состояния |
| recorder/ | Обнаружение потоков, управление записью, сборка временной шкалы, запись WAV |
| shared/ | Версия протокола, идентификаторы, структуры блоков и статусов |
| tests/ | Детерминированные проверки протокола, потерь, синхронизации и файлов |

## Передача аудио

Планируется локальная общая память и ограниченный кольцевой буфер для каждого экземпляра плагина. Один производитель — аудиопоток экземпляра; один потребитель — приёмная часть рекордера.

В аудиопотоке допустимы только ограниченные по времени действия с заранее подготовленной памятью. Выделение памяти, дисковые операции, блокировки и ожидание приложения-приёмника выносятся из него. При переполнении отправка не должна задерживать DAW; потеря отмечается счётчиками и метаданными.

Межпроцессную корректность атомарных операций, порядок публикации блоков и совместимость разрядности необходимо проверить на целевой платформе.

## Черновые метаданные блока

- Версия протокола.
- Идентификатор сессии и уникальный идентификатор экземпляра/потока.
- Порядковый номер блока.
- Позиция первого отсчёта и признак достоверности источника времени.
- Число кадров, каналов, частота дискретизации и формат отсчётов.
- Признаки разрыва, изменения формата и потерь.

Это перечень требований к данным, а не готовый бинарный ABI. Размеры полей, выравнивание, пределы буферов и проверка заголовков будут определены отдельно.

## Управление

Команды Record/Stop и состояние сессии отделены от передачи аудио. Рекордер выступает единственным владельцем состояния записи и подтверждает команды. В версии 0.1 команды поступают только из окна рекордера.

Вся версия 0.1 использует ручной запуск рекордера и Record/Stop в его окне. Управление из плагина отложено на следующую версию.

## Временная шкала

Нельзя считать независимые счётчики экземпляров общей шкалой времени. Позиция транспорта также может останавливаться или сбрасываться при смене песни.

Необходимо исследовать доступные временные данные Show Page и выбрать привязку всех потоков к общей шкале сессии. Проверка — одинаковые импульсы на нескольких каналах в начале и конце записи, включая остановку транспорта и переключение песен.

Разрывы должны сохранять временное положение следующего материала. При известной длительности разрыва возможна вставка тишины с записью события; если положение неизвестно, необходимо явно отметить невозможность точного выравнивания.

## Файлы и сбои

Дисковая запись выполняется вне аудиопотока DAW. Каждый поток получает отдельный файл внутри папки сессии. При Stop рекордер завершает приём согласованного диапазона и закрывает файлы.

До длительных записей выбрать RF64 или сегментацию, механизм сохранения служебных данных и восстановления незавершённых файлов. Перезапуск рекордера не должен ошибочно продолжать старую сессию или перезаписывать её файлы.

## Открытые решения

Средства разработки VST3 и GUI, механизм управляющих сообщений, правила обнаружения и очистки общей памяти, лимиты потоков и буферов, идентификация экземпляров после копирования и загрузки проекта, поведение при смене частоты дискретизации.

## Шаблоны разных Show

Рекордер хранит версионированные шаблоны с именами, порядком и выбором каналов, базовой папкой и параметрами записи. Выбор шаблона ручной. Состояние экземпляра плагина сохраняется в Show; шаблон хранит общую конфигурацию.

Определить устойчивые идентификаторы и правила перепривязки при копировании плагина, загрузке Show и конфликтах. Отсутствующий канал отображается как неподключённый; новые каналы требуют включения в конфигурацию. Каждый дубль получает снимок выбранной конфигурации. Во время записи изменения шаблона не должны молча менять текущую сессию.

MIDI — будущее расширение протокола. Сейчас передаётся и записывается только аудио.
