# Этап 2 — проверка Fender Studio Show Page

Целевой хост: Fender Studio 8.1.2 (113407), Windows 11 x64, 48 kHz, device/live buffer 128 samples.

Этот документ заполняется по результатам проверки минимального pass-through VST3 в реальном Show Page. На Этапе 2 shared memory и запись WAV ещё не участвуют.

## 1. Загрузка и прозрачность сигнала

- [x] `DAW Streamer.vst3` обнаруживается Fender Studio.
- [x] Плагин загружается на моно-канал — подтверждено на Guitar, диагностика показывает I/O `1 / 1`.
- [ ] Плагин загружается на стерео-канал.
- [x] На проверенном канале при A/B bypass нет слышимого изменения уровня, панорамы или окраски сигнала.
- [x] На проверенном канале нет слышимых щелчков или dropout при обычной работе.

## 2. Диагностическая сборка

Stage 2 Diagnostics добавляет в окно VST3 только наблюдение за хостом и не изменяет аудиосигнал.

Окно показывает:

- `processBlock`: `RUNNING`, если счётчик изменился за последние 100 мс, иначе `NO CALLBACKS`;
- общий `Callback count`;
- `Host is playing`;
- наличие `AudioPlayHead` и `PositionInfo`;
- `Time in samples`, PPQ, BPM и размер такта, если хост их предоставляет;
- sample rate, ожидаемый и фактический размер блока, число входных/выходных каналов.

Во время проверки окно плагина держать открытым. Для каждого режима дать состоянию 2–3 секунды и записать, продолжает ли расти `Callback count` и что происходит с временными данными.

### Первые подтверждённые наблюдения

Снимок диагностики на Guitar при остановленном транспорте:

- `processBlock = RUNNING` при `Host is playing = NO`;
- `AudioPlayHead = YES`, `PositionInfo = YES`;
- доступны `Time in samples`, PPQ, BPM и time signature;
- BPM корректно обновляется при переключении Song;
- sample rate = `48000 Hz`;
- `Expected block = 512 samples`, `Current block = 512 samples`;
- I/O = `1 / 1` (mono).

Важно: несмотря на настройку live/device buffer 128 samples, Fender Studio в этом экземпляре VST3 фактически вызывает `processBlock()` блоками по 512 samples. Для shared-memory транспорта и ring buffer на Этапе 3 нельзя жёстко предполагать размер блока 128; размер блока должен считываться динамически.

Рекомендуемый порядок оставшихся проверок:

1. На Play убедиться, что `Host is playing = YES`, `Callback count` растёт, а `Time in samples`/PPQ двигаются.
2. Включить bypass плагина на 5–10 секунд — проверить счётчик.
3. Снять bypass, затем Mute канала — проверить счётчик.
4. Если Show Page позволяет отдельно деактивировать канал/инструмент, проверить неактивный канал.
5. При переключении Song отметить, остаётся ли `processBlock = RUNNING` и сбрасываются ли/меняются `Time in samples` и PPQ.
6. Проверить один стерео-канал, например Playback, и убедиться, что I/O показывает `2 / 2`.

## 4. Временные данные хоста

Проверить данные, доступные через `AudioPlayHead::getPosition()`:

- [x] `getIsPlaying()` — доступно;
- [x] `getTimeInSamples()` — доступно;
- [x] `getPpqPosition()` — доступно;
- [x] `getBpm()` — доступно, корректно обновляется при смене Song;
- [x] `getTimeSignature()` — доступно.

Остаётся зафиксировать:

1. как `Time in samples` и PPQ ведут себя при Stop → Play;
2. сбрасываются ли они при переключении Song;
3. одинаково ли ведут себя в разных экземплярах плагина.

## Критерий завершения Этапа 2

Этап завершён, когда:

- VST3 успешно загружается в целевом Show Page и прозрачно пропускает mono/stereo signal;
- вручную проверены Stop, bypass, неактивный канал и переключение песни;
- зафиксирован фактический набор временных данных хоста и ограничения, важные для общей временной шкалы будущей записи.
