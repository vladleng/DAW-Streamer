# Этап 2 — проверка Fender Studio Show Page

Целевой хост: Fender Studio 8.1.2 (113407), Windows 11 x64, 48 kHz, device/live buffer 128 samples.

Этот документ фиксирует результаты проверки минимального pass-through VST3 в реальном Show Page. На Этапе 2 shared memory и запись WAV ещё не участвуют.

## 1. Загрузка и прозрачность сигнала

- [x] `DAW Streamer.vst3` обнаруживается Fender Studio.
- [x] Плагин загружается на моно-канал — подтверждено на Guitar, диагностика показывает I/O `1 / 1`.
- [x] Плагин загружается на стерео-канал — подтверждено, I/O `2 / 2`.
- [x] При A/B bypass нет слышимого изменения уровня, панорамы или окраски сигнала.
- [x] Нет слышимых щелчков или dropout при обычной работе.

## 2. Диагностическая сборка

Stage 2 Diagnostics добавляет в окно VST3 только наблюдение за хостом и не изменяет аудиосигнал.

Окно показывает:

- `processBlock`: `RUNNING`, если счётчик изменился за последние 100 мс, иначе `NO CALLBACKS`;
- общий `Callback count`;
- `Host is playing`;
- наличие `AudioPlayHead` и `PositionInfo`;
- `Time in samples`, PPQ, BPM и размер такта, если хост их предоставляет;
- sample rate, ожидаемый и фактический размер блока, число входных/выходных каналов.

## 3. Подтверждённое поведение Show Page

| Сценарий | processBlock вызывается? | Наблюдение |
| --- | --- | --- |
| Transport Play | **Да** | `Host is playing = YES`, timing обновляется |
| Transport Stop | **Да** | `Host is playing = NO`, callback продолжает идти |
| Plugin bypass | **Нет** | `Callback count` останавливается на время bypass |
| Mute канала | **Да** | Диагностика продолжает работать |
| Переключение Song Show Page | **Да** | Плагин остаётся работоспособным, host timing/BPM обновляются под выбранный Song |
| Mono | **Да** | I/O `1 / 1` |
| Stereo | **Да** | I/O `2 / 2` |

Отдельная деактивация канала не является опорным механизмом v0.1. Если Show Page полностью прекращает обработку канала, запись из соответствующего экземпляра VST3 естественно не может продолжаться; поэтому рабочая конфигурация концерта должна держать нужные sender-плагины активными.

## 4. Временные данные хоста

Через `AudioPlayHead::getPosition()` подтверждён доступ к:

- [x] `getIsPlaying()`;
- [x] `getTimeInSamples()`;
- [x] `getPpqPosition()`;
- [x] `getBpm()` — корректно обновляется при смене Song;
- [x] `getTimeSignature()`.

Также подтверждено:

- sample rate = `48000 Hz`;
- при настройке live/device buffer 128 samples фактический VST3 callback в проверенном Show Page приходит блоками по `512 samples` (`Expected block = 512`, `Current block = 512`).

Следствие для Этапа 3: размер блока нельзя жёстко считать равным настройке device buffer. Shared-memory транспорт и ring buffer должны принимать фактический `buffer.getNumSamples()` каждого callback.

## 5. Архитектурный вывод для записи

Состояние транспорта Fender Studio **не управляет записью Recorder**.

Для v0.1:

`Recorder Record -> непрерывная запись отделения -> Recorder Stop`

При Transport Stop `processBlock()` продолжает вызываться, поэтому sender может продолжать передавать поток между песнями. При bypass плагина callback прекращается, поэтому sender-плагины во время записи должны оставаться включёнными.

Host `Time in samples` / PPQ / BPM полезны как диагностические и метаданные, но **не должны быть мастер-таймлайном записи**. Общую временную шкалу многодорожечной записи на Этапе 3 следует вести на стороне Recorder собственным монотонным sample counter от начала дубля. Это делает запись независимой от Stop/Play, смены Song и возможных сбросов transport position.

## Критерий завершения Этапа 2

Этап 2 считается проверенным для требований v0.1:

- VST3 успешно загружается и прозрачно работает на mono/stereo;
- подтверждено поведение при Play, Stop, bypass, mute и переключении Song;
- подтверждён доступный набор host timing;
- выявлен фактический callback block size 512 samples при device buffer 128;
- зафиксировано, что Recorder управляет записью независимо от DAW transport, а мастер-таймлайн строится на стороне Recorder.
