# DAW Streamer — требования и критерии готовности

> **Актуальное состояние: v0.1 embedded Master Recorder.** Старые определения «прототип ещё не создан», «MIDI позже», «только отдельный Recorder.exe», «шаблоны в v0.1» более не применимы. Контекст: [handoff](current-handoff.md), [architecture](architecture.md), [roadmap](roadmap.md).

## Назначение

Писать полноценные отделения живого выступления из VST3-host/Show Page в отдельные синхронные WAV и MIDI, без второй DAW. Живой сигнал имеет приоритет. Пользователь размещает Sender в конкретной точке цепи; звук прозрачно проходит дальше. Для инструментов/VSTi запись после инструмента, до обработки; для живых источников — до обработки.

## Функции основного v0.1

- Один VST3 с режимами `Sender` и `Master Recorder`, отдельный процесс Recorder в основное распространение не входит.
- Ровно 4 фиксированных аудиослота, автоназначение; видимые имена `Inst 1`–`Inst 4` редактируемые и сохраняемые в Show; пользовательские WAV filenames.
- Одна Master-инстанция на постоянном Main/Master, сам мастер-шинный звук не записывается.
- 48 kHz / mono или stereo / 24-bit PCM WAV, внутренняя передача float32; текущая платформа Windows 11 x64.
- MIDI как дополнительный поток в существующем Sender, `MIDI.mid` Type 0 / 960 PPQ; без tempo map.
- Отдельные папки для двух отделений по ~40–50 минут; новый Record не перезаписывает старый take.
- Непрерывная запись относительно Recorder даже при Play/Stop DAW и смене Songs, если host продолжает callbacks; при bypass Sender host может перестать вызывать обработку.
- VST3 parameter `Recording` и state feedback (где host поддерживает); Record/Stop из любого экземпляра.
- Встроенные `Details`: Queue, Drop, Gaps, состояние источников; ошибки должны быть видны и воспроизводимы в диагностике.

## Обязательные требования к надёжности

- Не терять и не изменять доступные аудиосэмплы при штатном сценарии и длительной записи.
- Синхронизировать WAV и MIDI по одной общей timebase; после gaps не сдвигать более позднее аудио ради маскировки реальной потери.
- Не выполнять блокирующие операции в realtime callback.
- Не допускать неконтролируемого роста RAM/CPU/Queue при часовых дублях.
- Надёжно завершать Stop и запускать следующий take.
- Выявленные сбои #34 должны быть устранены или строго локализованы, с трассировкой причин вставки тишины и отдельной проверкой качества записанного звука.

## Acceptance gate v0.1.1 / эксплуатационная проверка

1. Windows x64 Release build и CTest зелёные; новые регрессионные тесты проверяют содержание WAV samples, а не одну лишь длину.
2. Реальный 60+ минутный take: четыре Sender + MIDI, обычная работа Show с переключением Songs и transport.
3. Ни одного необъяснённого общего разрыва; никаких новых слышимых щелчков/искажений, подтверждённо возникающих в capture path.
4. Сравнение MIDI↔Keys audio у начала, около 30-й минуты и на 55–60-й; проверка всех WAV; без накопительного drift.
5. Проверка `Drop`, `Gaps`, Queue, memory, CPU, ошибок; документирование вынужденных gap событий, если source сам перестаёт поставлять samples.
6. Принимает результат пользователь; до этого #31 остаётся открытым, #32/#20 не начинаются.
